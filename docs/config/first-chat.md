# 第一次对话

开口之前先对一遍：

1. WebUI 已打开，各页都点过 **保存配置**
2. **功能配置** 里选好了对话模型
3. 要用语音的话：ASR 总开关开着，且本地 ASR 已启动，或百度流式 ASR 已填好 Key
4. TTS 总开关开着，且只启用了一种发音方式
5. Live2D 主服务在跑，桌面上看得到角色

## 语音聊

对着麦克风说话。识别成功后角色会思考，再出声、出字幕。想打断就直接说话，或按 `Ctrl + G`。

![功能配置里打开 ASR / TTS](/images/first-chat-voice.png)

## 打字聊

1. 功能配置勾选 **文字输入框**
2. 保存配置并重启桌宠
3. 在桌宠的输入框里打字回车

![文字输入框开关](/images/first-chat-text.png)

## 混用检查：本地 ASR + 云端 TTS

| 项 | 期望 |
| --- | --- |
| 启动页 | ASR 卡片已启动；TTS 卡片可以没有 |
| 云端配置 | 恰好一种云端 TTS 为开 |
| 对话 | 你说话 → 本地识别文字 → LLM → 云厂商出声 |

![启动页：关注 ASR，不必强求 TTS](/images/mix-services-asr-not-tts.png)

## 三个最常见的卡点

- **完全没反应**：ASR 总开关没开，或本地 ASR 没启动，或系统没给麦克风权限。
- **有字幕没声音**：TTS 总开关没开，或云端 Key 没填，或同时开了多种 TTS，或本地 5000 端口没起来。
- **模型报错**：回 [LLM 配置](/config/llm) 检查 URL 是否带 `/v1`、模型名和控制台是否一致。

桌宠闪退或行为异常时，先看启动页的日志区，再看 `live-2d/runtime.log`。更多现象见 [常见问题](/faq)。
